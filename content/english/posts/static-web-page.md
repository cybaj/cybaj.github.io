This blog is a static web page: one delivered exactly as stored, as opposed to
a dynamic page that a web application generates per request.

The English Wikipedia article makes a point the Korean one doesn't — that
JavaScript on a page can introduce dynamic behaviour, so "static" describes how
the document is served rather than how it behaves once loaded
(`20260812-en-wikipedia-org-static-web-page.md`).

The Korean article spends its space elsewhere, on static site generators and
why managing many static files by hand is impractical without one
(`20260812-ko-wikipedia-org-정적-웹-페이지.md`). That is the argument for Hugo,
and the English lead never makes it.

Two articles, same topic, different emphases. They are not translations of each
other, which is why each is kept as its own reference.
